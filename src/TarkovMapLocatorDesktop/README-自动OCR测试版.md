# 塔科夫工具箱自动 OCR 测试版

版本：31.15.3（测试版 · PP-OCR 检测识别引擎 + 检视窗口触发）

这是一个与正式版**独立运行**的便携测试版本，目标是验证“默认无需手动选模板或调 OCR 框”的游戏内物品查价流程。默认跟随鼠标附近扫描；如有固定窗口位置的习惯，也可选择一块固定识别区域。

它只读取当前屏幕画面和本机行情缓存；不会读取游戏内存、不会修改游戏文件，也不会向游戏发送按键或鼠标操作。

## 31.15.3 更新：自定义识别区域 + 关窗即隐藏

- 识价页新增 **识别区域** / **清除区域** 按钮：框选一块固定区域后，识别只扫这块区域、不再跟随鼠标（适合检视窗口经常开在固定位置的习惯）；清除后恢复跟随鼠标。框选会在识别运行中自动重启并立即生效，选择会保存。
- 定位画面与识别使用同一块区域，便于核对框选是否正确。
- 关闭物品详情窗口后价签**立即消失**（约一帧内）：防闪烁的保持逻辑现在只在窗口仍然打开、单帧读字失手时生效。

## 31.15.2 更新：图标杂字、截字与价签抖动修复

- 标题前的放大镜图标即使与文字**粘连无空格**（如把 `UHF RFID…` 读成 `PUHFRFID…`）也能正确匹配了。
- 识别裁剪框加了内边距，修复首尾文字笔画被切导致的"字不全"。
- 价签位置改为**挂在窗口标题下方**（物品图片区左上角的深色底上），不再压住标题栏和关闭按钮。
- 价签防抖：同一物品的小幅位置浮动不再挪动窗口；偶发一帧识别失手时价签保持显示，不再闪烁。

## 31.15.1 更新：只在物品检视窗口打开时识价

- 识价现在**只在物品详情/检视窗口（带重量 `kg` 行的界面）打开时触发**，读取的是窗口标题栏的物品名。
- 在仓库里悬停格子、格子上的物品短名，**不会再触发价格**——彻底解决"还没点开详情就乱弹价格"的问题。
- 判定方式：先找窗口右上角必有的"`0.010 kg`"重量行（文字识别，天然适配任何分辨率），找到后再读它左上方的窗口标题。
- 标题前的放大镜图标偶尔会被读成一个多余字符（如 `Q ULTRA…`），程序会自动尝试剥掉行首杂字再匹配。

## 31.15.0 更新：整套识别引擎已更换

- 旧版“kg 模板锚点 + 多尺度匹配 + Tesseract”管线已整体替换为 **PP-OCRv4 文字检测 + 文字识别**（本地 ONNX 模型，完全离线）。
- 不再依赖任何模板图片：检测模型直接找出鼠标附近的所有文字行，识别模型直接读出文字内容。
- 分辨率、游戏 UI 缩放不再需要适配——文字框的位置和大小由检测模型给出，天然适配任何缩放。
- 中英混排（如 `AK-74M 5.45x39 突击步枪`、`LEDX`）识别精度大幅提升。
- 单帧开销显著下降：检测约 30~80 毫秒，每行识别约 10~30 毫秒，不再有多尺度全量扫描的 CPU 峰值。

## 这版与正式版的区别

- 正式版的 OCR 查价可保存自定义模板、截图范围和框体位置。
- 测试版不需要模板：PP-OCR 检测模型自动定位鼠标附近的文字行并逐行识别。
- 测试版不需要你设置模板或 OCR 框；这些旧版校准入口不会作为日常操作入口显示。
- “识别区域”是可选项：只有想让识别始终扫固定区域时才使用；“清除区域”或“自动修复”会恢复跟随鼠标。
- 测试版使用独立的本地目录，不会改写正式版配置：`%LOCALAPPDATA%\TarkovMapLocatorDesktopAutoOcrTest`。
- 任务物品缓存仍与地图工具共用，便于直接测试已有数据；行情、OCR 设置、运行日志则隔离保存。

## 启动前准备

1. 解压整个测试版目录，不要只单独复制 EXE。
2. 双击 `TarkovMapLocatorAutoOcrTest.exe`。
3. 打开《逃离塔科夫》，进入能看到物品信息提示的界面。
4. 首次启动会自动导入随包附带的行情缓存；联网刷新行情仍可获得更新价格，但不是启动 OCR 的必需条件。

建议使用无边框窗口或全屏窗口模式进行测试。独占全屏通常也可用，但如果画面抓取异常，优先改为无边框窗口再试。

## 最短使用流程

1. 在左侧导航进入 **OCR 查价**。
2. 选择需要的价格来源：`PVP` 或 `PVE`。
3. 点击 **启动自动识别**。
4. 切回游戏，**双击物品（或右键 → 检视）打开物品详情窗口**。
5. 窗口打开后约 0.5 秒内，屏幕上会出现透明的价格文字，显示物品名称、跳蚤价、最低商人价等信息。
6. 不再使用时，切回测试版点击 **停止识别**。

> 重点：识价只在物品详情窗口打开时触发。仓库里单纯悬停不会出价——这是刻意设计，避免把邻近格子的物品名误当成目标。鼠标保持在窗口附近（搜索以鼠标为中心）。

## 自动定位是怎么工作的

每次识别时，测试版会：

1. 优先确认前台窗口是否为《逃离塔科夫》，并抓取鼠标周围的一块区域（约 960×720），而不是扫整块桌面。
2. 用 PP-OCR 检测模型找出这块区域内的所有文字行。
3. 在靠近鼠标的短文字行里寻找“数字 + kg”的**重量行**——它是“物品详情窗口已打开”的开关；没有它就直接跳过本帧。
4. 找到重量行后，在它左上方的窗口标题区域读出标题文字，与本机行情缓存匹配，命中的标题行就是价格悬浮窗的锚点。

没有模板、没有 OCR 框或缩放比例需要校准；每一帧都会独立完成识别。仅当你主动设置“识别区域”时，工具会记住该固定范围。

## 看到什么状态算正常

| 状态文字 | 含义 | 你该做什么 |
| --- | --- | --- |
| `等待物品详情窗口：…` | 没有检测到打开的物品详情窗口（重量 kg 行） | 双击物品打开详情窗口，鼠标保持在窗口附近 |
| `已定位物品窗口，但未能读到窗口标题文字` | 找到了窗口，但标题读取失败 | 确认标题未被遮挡；把鼠标移近窗口再试 |
| `识别确认中：…` | 已读到候选名称，正在做连续帧确认 | 保持不动，避免闪烁时误报 |
| `识别中：…` 并出现价格文字 | 正常识别成功 | 可继续查看下一个物品 |
| `未匹配行情：…（共 N 行）` | 读到了窗口标题，但本地行情中没有足够可靠的同名物品 | 尝试刷新行情；如果仍存在，请反馈截图和文字 |

## 识别不到时怎么处理

按下面顺序排查，不需要手动调框：

1. 确保塔科夫是前台窗口，且物品提示框已经完全显示。
2. 将鼠标移到物品名称文字的附近，不要停在物品格子的中心空白处。
3. 等待约 1 秒，再尝试另外一个普通物品。
4. 如果使用了 HDR、第三方字体替换、强烈的画面滤镜，先临时关闭再测试（这些会改变截屏画面本身）。
5. 仍失败时打开 **查看定位画面** 或 **窗口化定位画面**，按“反馈信息”一节提供截图。

新引擎每帧独立识别；**自动修复** 会清除固定识别区域和旧版定位记录，恢复为鼠标附近自动扫描。

## 定位画面（只用于反馈）

正常使用不需要打开定位画面。

- **查看定位画面**：在测试版页面内显示当前鼠标附近被抓取的区域。
- **窗口化定位画面**：弹出可调整大小的独立窗口，便于在游戏旁边观察或截图。
- 两种画面都支持滚轮缩放；在空白处按住鼠标可拖动平移。
- 画面中的红框、绿框、蓝框分别是物品标题、重量 kg 和价格悬浮窗位置的反馈提示。

测试版将这些画面保留为“问题反馈工具”，并不要求、也不支持在 PP-OCR 自动模式中拖动或保存标题／重量框；可用滚轮缩放、在空白处拖动平移。点击 **自动修复** 会回到鼠标附近自动扫描。

## 建议测试项目

为了判断自动适配是否可靠，建议至少各试一次：

- 1920×1080、2560×1440、3840×2160，或你自己的实际分辨率。
- 游戏 UI 缩放的默认值及你平常使用的缩放值。
- PVP 和 PVE 行情模式。
- 中文名称较长的物品、钥匙、药品、弹药等不同类型。
- 无边框窗口和你常用的显示模式。

每种情况先挑 3～5 个常见物品，鼠标稳定停留后观察是否连续显示正确价格。

```text
Windows 分辨率 / 缩放：
游戏分辨率 / 显示模式：
游戏 UI 缩放：
PVP 或 PVE：
测试的物品名称：
页面状态文字：
是否点过“自动修复”：
定位画面截图：

```

运行日志在：

```text

```

只需要提供与问题发生时间相近的一段日志即可；日志不包含游戏截图文件。

## 已知边界

- 识别对象是鼠标附近的文字行。如果鼠标附近同时有多个物品名称文字（例如密集的仓库格子），有小概率把邻近物品的名字先匹配上；把鼠标停到物品提示（悬浮框）上最可靠。
- 识别成功也依赖行情缓存中存在该物品；名称读出后“未匹配行情”不等于自动定位失败。
- 自动定位默认只针对当前鼠标附近区域，目的是减少误识别和性能占用；它不是全屏持续扫描器。只有用户主动设置“识别区域”后才会改为扫描该固定范围。
- 开启 Windows HDR 时，屏幕截取的画面会整体泛白，可能影响识别质量；建议测试时暂时关闭 HDR。
- 测试版不会覆盖正式版的 OCR 设定、市场缓存或日志。要回到正式版，直接启动原来的 `TarkovToolbox.exe` 即可。

## 引擎与许可

本测试版内置 PaddleOCR 的 PP-OCRv4 检测/识别模型（Apache-2.0）与 Microsoft ONNX Runtime（MIT），全部本地运行，识别过程不联网。
